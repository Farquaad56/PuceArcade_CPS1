# 05 — CPS2 (spec digérée depuis MAME 0.287)

Sources : `ref/mame-cps2/cps2.cpp` et `ref/mame-cps2/cps2crypt.cpp` (MAME 0.287, BSD-3-Clause), base commune déjà portée :
`ref/mame-cps1/cps1.cpp`, `ref/mame-cps1/cps1_v.cpp`. Le CPS2 de MAME est la classe `cps2_state : cps_state` : tout ce qui
n'est pas redéfini ici est le code CPS1 déjà porté (tilemaps, palette, CPS-A/CPS-B, `cps1_get_video_base`, QSound).
Décisions d'architecture : ADR-006 (CPS2 dans le projet), ADR-007 (horloge du 68000).

## Système et jeux pris en charge
- Catalogue : 324 lignes `GAME` de cps2.cpp (40 parents), table `GAMES2` générée (`tools/extract_romsets.py --cps2`).
- Machines (`cps2.cpp` l.1801-1880) : `cps2` (269 jeux), `dead_cps2` (46, versions Phoenix : carte « suicidée », RAM et sortie
  déplacées), `cps2comm` / `dead_cps2comm` (8, carte réseau de ssf2tb), `gigaman2` (1, bootleg sans QSound).
- **Pris en charge** : machines `cps2` et `dead_cps2` ; inits `init_cps2` et `init_singbrd`. **Hors champ** : `cps2comm`,
  `dead_cps2comm`, `gigaman2`, `init_pzloop2` (paddle), `init_ecofghtr` (molette), et les jeux `MACHINE_NOT_WORKING` (aucun en 0.287).
- Système d'un jeu : CPS2 si `machine` vaut `cps2`, `dead_cps2`, `cps2comm`, `dead_cps2comm` ou `gigaman2` ; CPS1 sinon.

## Horloges (ADR-007)
- 68000 : `M68000(config, m_maincpu, 16_MHz_XTAL)` (l.1804) puis `set_clock_scale(0.7375)` (`init_cps2nc`, l.11013) :
  16 MHz × 0,7375 = **11,8 MHz**. 0,7375 = 59/80, donc un cycle = 5 040 000 000 / 11 800 000 = **25 200 / 59 ticks**
  (≈ 427,12). Accumulateur entier : à chaque cycle, `acc += 25200 ; ticks = acc / 59 ; acc %= 59` (427 ou 428 ticks, moyenne exacte).
- Z80 : 8 MHz (l.1812) = 630 ticks par T-state (`TICKS_PER_Z80_QSOUND`), IRQ0 tenue toutes les 8 MHz / 32 000 = 250 Hz (l.1815-1816),
  comme les cartes QSound du CPS1. DSP QSound identique (60 MHz, 24 038,46 Hz, ADR-005).
- Écran : mêmes paramètres que le CPS1 (`set_raw(CPS_PIXEL_CLOCK, ...)`, l.1822) : 630 ticks par pixel, 322 560 par ligne,
  262 lignes, VBLANK à la ligne 240, trame de 84 510 720 ticks (59,637 Hz).

## Romsets
- Régions conservées : `maincpu` (CODE_SIZE = 0x400000, `ROM_LOAD16_WORD_SWAP`), `gfx` (`ROM_LOAD64_WORD`, jusqu'à 0x2000000),
  `audiocpu` (QSOUND_SIZE = 0x50000, ROM Z80 **en clair** + `ROM_CONTINUE`), `qsound` (échantillons), `key` (0x20 octets,
  fichier `.key` de 0x14 octets ; `phoenix.key` pour les versions Phoenix). `user1` (1944) n'est pas utilisée par le CPS2.
- Graphismes : après chargement, `cps2_gfx_decode` (l.789-796) applique `unshuffle` (l.768-786) à chaque banque de 0x200000 octets,
  vue comme un tableau de `uint64_t` (blocs de 8 octets déplacés entiers ; l'ordre des octets dans un bloc ne change pas).
  `unshuffle(buf, len)` : si len == 2 rien ; sinon len /= 2, unshuffle(buf, len), unshuffle(buf + len, len), puis pour
  i < len / 2 : échanger buf[len/2 + i] et buf[len + i]. Le format des tuiles décodées est ensuite celui du CPS1 (`gfx_cps1`).
- Programme : région `maincpu` en mots gros-boutistes (octet fort d'abord, comme le CPS1) ; opcodes déchiffrés de même taille.

## Chiffrement (cps2crypt.cpp, init_cps2crypt)
- Seules les lectures « programme » du 68000 sont chiffrées : MAME sert l'espace `AS_OPCODES` (`decrypted_opcodes_map`,
  l.1358-1361 : 000000-3FFFFF) pour tout cycle de bus dont le code fonction est programme (FC = 2 ou 6), y compris les extensions
  et les lectures relatives au PC (m68000gen.py choisit l'espace selon le FC du microcode). `puce-m68k` passe ce FC au `Bus`
  (`AddrSrc::EaProg` → FC programme). Règle : `fc & 3 == 2` et adresse < 0x400000 → mot des opcodes déchiffrés ; sinon bus normal.
- Clé (`init_cps2crypt`, l.10955-10995) : 160 bits du fichier .key → `decoded[10]` (mots de 16 bits) : pour b de 0 à 159,
  `bit = (317 - b) % 160` ; si `(key[bit / 8] >> ((bit ^ 7) % 8)) & 1` alors `decoded[b / 16] |= 0x8000 >> (b % 16)`.
  `master_key[0] = decoded[0] << 16 | decoded[1]`, `master_key[1] = decoded[2] << 16 | decoded[3]`.
  Si `decoded[9] == 0xFFFF` (carte morte, Phoenix) : lower = 0xFF0000, upper = 0xFFFFFF (aucun mot de la ROM déchiffré) ;
  sinon lower = 0, upper = (((~decoded[9] & 0x3FF) << 14) | 0x3FFF) + 1. Appel : `cps2_decrypt(rom, dec, 0x400000, key, lower / 2, upper / 2)`.
- `cps2_decrypt` (l.635-713) : pour chaque i de 0 à 0xFFFF : seed = FN1(i) ; sous-clé = expand_subkey(seed) XOR master_key ;
  clé 2 = expand_2nd_key(sous-clé) (+ bits supplémentaires l.689-696) ; pour a = i, i + 0x10000, … < length / 2 :
  si `lower_limit <= a <= upper_limit` (bornes **incluses**, en mots) `dec[a] = FN2(rom[a], clé 2)`, sinon `dec[a] = rom[a]`.
- Oracle : `tests-data/cps2crypt/vectors.txt`, produit par `tools/cps2crypt_golden.cpp` qui compile cps2crypt.cpp tel quel :
  ROM synthétique `rom[a] = (a × 0x9E37 + 0x1234) & 0xFFFF` (0x200000 mots), 5 clés (dont tout à 0xFF et une limite haute à
  0x100000 octets) ; par clé : key0, key1, lower, upper, CRC-32 des mots en gros-boutiste, 16 mots témoins.

## Ports d'entrée (actifs bas sauf mention)
- Disposition « 4 joueurs » (`cps2_4p4b` l.1407-1554 et dérivés 4p/3p/2p/1p à 1-4 boutons) :
  IN0 = joueur 1 (bits 0-7 : droite, gauche, bas, haut, B1, B2, B3, B4), joueur 2 (bits 8-15, même ordre) ;
  IN1 = joueur 3 (bits 0-7), joueur 4 (bits 8-15) ; IN2 : bit 0 = DO EEPROM (actif haut), bit 1 = test (service), bit 2 = service 1,
  bits 3-7 = 1, bits 8-11 = start 1-4, bits 12-15 = pièce 1-4.
- Disposition « 6 boutons » (`cps2_2p6b` l.1679-1691, `cps2_2p6bt`, `cybots`) : IN0 comme ci-dessus avec B1-B3 (bits 4-6, 12-14),
  bit 7 et bit 15 à 1 ; IN1 : bit 0 = B4 J1, bit 1 = B5 J1, bit 2 = B6 J1, bit 4 = B4 J2, bit 5 = B5 J2, autres bits à 1 ;
  IN2 bit 14 = B6 J2 (à la place de la pièce 3).
- Disposition « qndream » (l.1752-1766) : IN0 bits 0-3 = B4, B3, B2, B1 du J1, bits 8-11 = B4, B3, B2, B1 du J2, autres à 1.
- (joueurs, boutons) par port, pour le frontal : 4p4b (4,4) 4p3b (4,3) 4p2b (4,2) 3p4b (3,4) 3p3b (3,3) 3p2b (3,2) 2p6b (2,6)
  2p6bt (2,6) 2p4b (2,4) 2p3b (2,3) 2p2b (2,2) 2p1b (2,1) 1p4b (1,4) 1p3b (1,3) 1p2b (1,2) cybots (2,4) qndream (2,4) choko (1,3).
- Volume (804030, l.1212-1234) : niveau 39 (maximum, `init_digital_volume` l.10937) → `cps2_vol_states[39]` = **0xE021**
  (bit 14 = 1 : pas de mémoire additionnelle, bit 15 = 1 : pas d'adaptateur réseau) ; `init_singbrd` → **0xD000**.

## Port 804040 (cps2_eeprom_port_w l.1121-1189)
- Octet fort (uds) : EEPROM : DI = bit 12, CLK = bit 13, CS = bit 14 du mot, appliqués dans cet ordre (champs du port EEPROMOUT,
  l.1458-1461) ; chaque ligne n'agit que si elle change (méthodes `di_write` / `clk_write` / `cs_write` existantes).
- Octet faible (lds) : bit 3 = 0 → Z80 tenu en reset (`INPUT_LINE_RESET` ASSERT), bit 3 = 1 → relâché ; compteurs et verrous de
  pièces ignorés. Au démarrage, le Z80 tourne (ligne non tenue) jusqu'à la première écriture.
- EEPROM : `EEPROM_93C46_16BIT` (l.1818) : 64 mots de 16 bits, 6 bits d'adresse, commandes de 2 + 6 bits ; DO lu en IN2 bit 0.

## Son
- Même carte que les jeux QSound du CPS1 (`qsound_sub_map`, ref/mame-cps1/cps1.cpp l.663-672), mais **Z80 non chiffré** :
  opcodes = données de la région audiocpu. Banques de 16 Kio : `(QSOUND_SIZE - 0x10000) / 0x4000` = 16 entrées (l.1794-1798).
- Côté 68000 : seule la RAM partagée 1 est visible, en 618000-619FFF (pas de RAM 2 ni de ports F1C0xx).
- Z80 tenu en reset : il n'exécute rien ; DSP et IRQ périodique continuent. Au relâchement, il repart de son état de reset.

## Vidéo (cps2.cpp l.756-1112)
- Configuration CPS-B : jeu « cps2 » de `cps1_v.cpp` (`CPS_B_21_DEF`, `mapper_cps2`), choisie par défaut pour un nom inconnu.
- Registres output (l.756-763) : mot 0 OBJ_BASE, 1 UNK1, 2 OBJ_PRI (priorités), 3 UNK2, 4 OBJ_XOFFS, 5 OBJ_YOFFS.
- RAM objets : `m_cps2_obj_size` = 0x2000 octets (0x1000 mots) ×2 (objram1, objram2), remises à 0 au démarrage (l.799-813).
  Banque (`cps2_objram_bank_w` l.817-821) : `objram_bank = data & 1` si octet bas écrit. `objram1_w` / `objram2_r` / `objram2_w`
  (l.823-853) : banque 1 → les deux RAM sont échangées. `cps2_objbase` (l.855-869) : banque 0 → objram1, banque 1 → objram2.
- Latch au VBLANK (`cps2_objram_latch` l.1105-1112, après `screen_vblank_cps1`) : `pri_ctrl = output[2]` puis copie de
  `cps2_objbase()` (0x1000 mots) dans `buffered_obj`. Le tampon de sprites **CPS1** n'est jamais latché sur CPS2 (reste à 0).
- `find_last_sprite` (l.872-894) : appelle d'abord celui du CPS1, puis cherche dans `buffered_obj` le premier offset (pas de 4)
  où `base[o+1] >= 0x8000 || base[o+3] >= 0xFF00` → `last = o - 4` ; sinon `last = 0x1000 - 4`.
- Sprites (`cps2_render_sprites` l.896-1038) : de `last` à 0 par pas de 4 ; x = base[i], y = base[i+1], priorité = (x >> 13) & 7,
  code = base[i+2] + ((y & 0x6000) << 3), colour = base[i+3], col = colour & 0x1F ; xoffs = 64 − output[4], yoffs = 16 − output[5] ;
  si colour & 0x80 : x += output[4], y += output[5] ; blocs si colour & 0xFF00 (nx = ((colour >> 8) & 0xF) + 1, ny = (colour >> 12) + 1),
  4 cas de flip (l.947-1026, cas sans flip : code `(code & ~0xF) + ((code + nxs) & 0xF) + 0x10 * nys`) ; positions `& 0x3FF` ;
  tuile 16×16 `prio_transpen` avec le masque `primasks[priorité]`, transparence 15, **sans mapper** (code direct) ;
  écran retourné : flips inversés et position (512 − 16 − sx, 256 − 16 − sy).
- Composition (`render_layers` l.1040-1102) : l0..l3 du layer control ; `lNpri = (pri_ctrl >> 4 × lN) & 0xF` ; retrait de la couche
  sprites CPS1 (3 tests en cascade) ; masques mask0 = 0xAA, mask1 = 0xCC et `primasks[0..8]` (l.1077-1095) ; dessin
  `cps1_render_layer(l0, 1)`, `(l1, 2)`, `(l2, 4)` : tilemaps LAYER1 avec **pri |= valeur** sur chaque pixel dessiné
  (tilemap.cpp : `pri = (pri & (pcode >> 8)) | pcode`, priority_mask 0xFF), couche 0 = sprites CPS1 ; puis sprites CPS2.
  La priorité de `prio_transpen` : pixel dessiné si `((1 << (pri & 0x1F)) & pmask) == 0`, puis pri = 0x1F (drawgfx, déjà porté).

## Raster et interruptions
- `init_cps2_video` (l.10948-10952) appelle `init_rasters` : compteurs raster actifs (`cps_gfx::raster::Raster`, T702, ADR-003).
- `raster_scanline` (ref/mame-cps1/cps1.cpp l.372-397) à chaque ligne, numérotée depuis le début de trame (ligne 0 = début de
  trame, VBLANK à 240) : si un compteur atteint 0, IRQ4 (IPL2) `counter[2] × 2` pixels plus tard (`raster_irq` l.399-405, qui
  appelle aussi `update_partial(vpos)`) ; à la ligne 240 : IRQ2 (IPL1). IPL1 + IPL2 = niveau 6 (`set_interrupt_mixer(false)`).
- Lectures CPS-B des registres raster : `ref/mame-cps1/cps1_v.cpp` l.2136-2181 (`cps1_cps_b_r`, 0x0E utilise `hpos`, position
  horizontale en pixels depuis le début de la ligne) ; écritures l.2183-2215 (`cps1_cps_b_w`).
- Acquittement (`irqack_r` l.407-417) : autovecteur, efface IPL1 et IPL2 (déjà porté).

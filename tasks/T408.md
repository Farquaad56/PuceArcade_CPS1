## Spécification (décidée, ne pas réinterpréter)
Sur le modèle de `ref/puce16-neogeo/ng-core/state.rs` : `pub fn save_state(&mut self) -> Vec<u8>` (appelle d'abord `finish_instruction()`, puis sérialise avec bincode : en-tête `b"CPS1"` + version u32 = 1 + nom du jeu + `cpu.state()` + état Z80 (puce-z80, feature serde) + état du port de broches de la SoundBoard + `Bus68k` (ram, inputs, dips, coinctrl) + `Video` (serde, sans `cfg`) + `SoundBoard` (ram, bank, latches, time) + `Chips` (ym, oki, oki_next, oki_current) + now, next_vblank, frame, ipl1, ipl2) et `pub fn load_state(&mut self, data: &[u8]) -> Result<(), String>` (refuse un autre jeu ou une autre version ; appelle `video.relink()`). Les ROM (maincpu, audiocpu, oki, gfx) ne sont PAS sérialisées. Les structures des autres crates ont déjà `cfg_attr(feature = "serde", derive(...))` (règle des cartes) : si l'une manque, l'ajouter dans `docs/QUESTIONS.md` et passer `blocked` (ne pas modifier l'autre crate ici). Q-M68KSTATE de Neo Geo s'applique (état STOP non sauvegardé) : sauvegarder uniquement à une frontière d'instruction hors STOP, sinon avancer d'une instruction.

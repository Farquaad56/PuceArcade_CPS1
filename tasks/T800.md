## Spécification (décidée, ne pas réinterpréter)
`romsets2_data.rs` est déjà généré par `python tools/extract_romsets.py --cps2` (table `GAMES2`, constantes `RS2_*`) et vérifié par le gate : ne jamais l'éditer.
1. `lib.rs` : `#[rustfmt::skip] pub mod romsets2_data;` (à côté de romsets_data) ; réexporter `romset::{system_of, System}` et `support::supported_games2`.
2. `romset.rs` : `#[derive(Clone, Copy, Debug, PartialEq, Eq)] pub enum System { Cps1, Cps2 }` ; `pub fn system_of(info: &GameInfo) -> System` : `Cps2` si `info.machine` ∈ ["cps2", "dead_cps2", "cps2comm", "dead_cps2comm", "gigaman2"], sinon `Cps1`. `find_game` cherche dans `romsets_data::GAMES` puis dans `romsets2_data::GAMES2`.
3. `support.rs` : pour un jeu CPS2 (`system_of`), machines acceptées `["cps2", "dead_cps2"]` et inits `["init_cps2", "init_singbrd"]` (mêmes variantes `Support` que le CPS1, même ordre de tests : machine, init, not_working). Les listes CPS1 ne changent pas. `supported_games()` reste CPS1 seulement (le pilote en dépend) ; nouvelle `pub fn supported_games2() -> Vec<&'static GameInfo>` = `GAMES2` filtrés par `support_of == Ok`, dans l'ordre de la table.
4. `dips.rs` : `input_layout` : si le nom est absent de `dips_data::INPUTS`, chercher dans une constante `INPUTS2: [(&str, u8, u8); 12]` écrite dans dips.rs (spec: docs/spec/05 §Ports d'entrée) : cps2_4p4b (4,4), cps2_4p2b (4,2), cps2_3p3b (3,3), cps2_2p6b (2,6), cps2_2p6bt (2,6), cps2_2p3b (2,3), cps2_2p2b (2,2), cps2_2p1b (2,1), cps2_1p2b (1,2), cybots (2,4), qndream (2,4), choko (1,3) ; sinon (2, 3) comme aujourd'hui.

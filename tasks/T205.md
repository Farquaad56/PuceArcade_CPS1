## Spécification (décidée, ne pas réinterpréter)
Le rendu travaille sur un bitmap « écran MAME » : `pub const BITMAP_W: usize = 512; pub const BITMAP_H: usize = 262;` (u16 = pen) et un bitmap de priorité u8 de même taille ; rectangle de clip `x 64..=447, y 16..=239` (`pub const CLIP: (usize, usize, usize, usize) = (64, 447, 16, 239)`).
```rust
pub fn find_last_sprite(obj: &[u16], kludge: i32) -> i32;           // l.2684-2718 (branche kludge&15 == 3 comprise)
impl Video {
    pub fn render_sprites(&mut self, gfx: &[u8], bitmap: &mut [u16], pri: &mut [u8], flip: bool);   // l.2720-2866 sur self.buffered_obj et self.last_sprite
}
pub fn prio_transpen16(gfx: &[u8], bitmap: &mut [u16], pri: &mut [u8], code: u32, color: u32, flipx: bool, flipy: bool, sx: i32, sy: i32, pmask: u32);
```
`prio_transpen16` (drawgfx.cpp l.910-938 + drawgfxt.ipp l.216-227) : layout L16x16, `pmask |= 1 << 31`, couleur de base `(color % 0x80) * 16` ; pour chaque pixel (x, y) de 0..16 (source lue en 15-x / 15-y si flip) dont la destination (sx+x, sy+y) est dans CLIP : si `v != 15` : si `(1u32 << (pri & 0x1F)) & pmask == 0` -> bitmap = base + v ; puis `pri = 31` (même si non dessiné). Pas de rebouclage.
`render_sprites` : itération sur les entrées k = 0..=last/4 dans cet ordre (PORT-NOTE de spec 02 ; `bootleg_kludge` bit 6 : ordre inverse comme l.2742-2750) ; code mappé SPRITES (-1 : sprite ignoré) ; DRAWSPRITE avec pmask 0x02 ; flip écran : position `(512-16-sx, 256-16-sy)` et flips inversés. Blocs : formules exactes de l.2777-2853.

## Tests à écrire (valeurs exactes)
- find_last_sprite : obj[3] = 0xFF00 -> -4 ; obj[7] = 0xFF00 (et obj[3] = 0) -> 0 ; aucun marqueur dans 0x400 mots -> 0x3FC ; avec kludge 3 : marqueur = obj[o+1] >= 0x8000.
- gfx = vec![0xFF; 0x8000] (tout transparent) ; tuile 16x16 code 1 : gfx[128+0..3] = [0x7F,0x7F,0x7F,0xFF] -> pixel (0,0) raw 8. ghouls (DM620 : code 1 -> 1). Entrée 0 = [x=100, y=50, code=1, attr=0x0002], entrée 1 attr = 0xFF00 ; last = find_last_sprite -> 0 ; render_sprites : bitmap[50*512+100] == 0x28 et pri[...] == 31 ; un pixel voisin (101,50) inchangé.
- pri[50*512+100] = 1 avant le rendu : bitmap inchangé, pri devient 31.
- Deux sprites au même point : entrée 0 couleur 2, entrée 1 couleur 3, entrée 2 = marqueur : le pixel vaut 0x28 (l'entrée 0, dessinée en premier, bloque l'entrée 1 via pri = 31).
- Bloc attr = 0x0102 (nx = 2) code 0x10 : sous-sprites codes 0x10 (x) et 0x11 (x+16) ; avec flipX (attr 0x0122) : code 0x11 en x et 0x10 en x+16.
- Clip : x = 440 -> seuls les pixels x <= 447 sont écrits ; x = 0x3F8 -> x & 0x1FF = 0x1F8 = 504 : rien d'écrit (pas de rebouclage).
